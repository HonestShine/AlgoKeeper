## 1. 产品概述

### 1.1 背景

算法学习者（以备战技术面试的 LeetCode 刷题群体为主）普遍面临「写题解」与「复习题解」互相割裂的问题：

- **通用笔记软件（Obsidian / Notion）**：灵活但缺乏算法题解的结构化模板——解法块、复杂度分析、题号/难度/标签没有统一规范，自然也就无法支撑「按复习计划调度」。
- **纯间隔重复软件（Anki）**：擅长短问答卡对抗遗忘，但**不适合存储长代码题解**——一段带多解法和复杂度推导的文章无法被压成一张卡，编辑与渲染体验也差。
- **网页题解站（LeetCode 题解区、博客）**：无法离线使用，且只是静态资料，**没有任何基于个人记忆状态的复习调度**。

### 1.2 核心价值主张

> **将「写题解」与「复习题解」深度融合在同一个工作流，通过 SM-2 间隔重复算法对抗遗忘，让算法知识沉淀为长期记忆。**

AlgoKeeper 不做「又一款 Markdown 笔记」或「又一款背单词卡」，而是面向算法题目这一**结构化 + 长文本**的特殊知识形态，把 Typora 式书写体验与 Anki 式调度放到同一处，并用「题目」作为组织与复习的天然锚点。

### 1.3 竞品定位对照

| 维度 | Obsidian | Anki | 网页题解站 | **AlgoKeeper** |
|---|---|---|---|---|
| 结构化题解模板（解法/复杂度/难度/标签） | 需自建 | ✗ 不适合 | 只读 | **内建** |
| 长代码 + 公式渲染 | ✔ | ✗ | ✔（需联网） | ✔ |
| 间隔重复调度 | ✗ | ✔ | ✗ | ✔（SM-2，按题/按卡） |
| 本地离线 & 数据自控 | ✔ | ✔ | ✗ | ✔ |
| 键盘驱动复习会话 | ✗ | 半 | ✗ | ✔ |
| 面向算法场景的统计洞察 | ✗ | 泛化 | ✗ | ✔ |

### 1.4 术语表

| 术语 | 英文 | 含义 |
|---|---|---|
| 题解（一条） | Note | 一道题目对应的 `.md` 文件，含 frontmatter 元数据 + 正文 |
| 题解集 | Note collection | 用户本地目录下全部 `.md` 题解 |
| 来源 / 题号 | source / id | 题目出处（内建 `leetcode`）及其平台内稳定标识，二者联合唯一 |
| 解法块 | SolutionBlock | 题解正文中一种解法的结构化区块，含思路与独立复杂度 |
| 整题卡 | whole card | 一道题默认的复习单位：看题名闭卷回忆完整解法 |
| 拆解卡 | split card | 由正文中 `问题::答案` 块派生、独立调度的问答卡 |
| 复习 | Review | 一次「看题→回忆→看答案→自评」的闭环 |
| 到期 | Due | 按调度规则，今日应复习的卡片集合 |
| 正确率 | Accuracy | 单次复习中评分 ≥3（Good/Easy）的占比 |

## 3. 产品原则与范围

### 3.1 产品原则（NFR-1 ~ NFR-5）

- **NFR-1 本地优先与数据自主**：所有题解以 `.md` 纯文本存储在用户指定的本地文件夹，文件含完整元数据（含复习变量），即使用户卸载应用或删除 SQLite 索引，文件仍可用任何文本编辑器打开，内容与复习进度可重新导入。应用**不强制绑定云账户**。
- **NFR-2 键盘驱动**：≥90% 核心操作（新建、保存、搜索、复习评分、切换模式）有快捷键映射，复习会话**全程无鼠标可达**。
- **NFR-3 渐进式复杂度**：首次打开只见空白编辑器与引导提示；复习调度器、统计看板等能力随使用深度自然浮现，不造成新手认知负担。
- **NFR-4 跨平台**：Windows 10+ / macOS 11+ / Linux（Debian/Ubuntu）。
- **NFR-5 数据不丢**：任何写入（含自动保存、复习后批量更新 frontmatter）必须是原子的，崩溃不损坏文件。

### 3.2 MVP 范围

MVP 覆盖四模块的核心闭环：**记录一条题解 → 系统按 SM-2 生成复习计划 → 每日到期 → 键盘会话复习 → 元数据/标签自动沉淀 → 检索与看板反哺**。

### 3.3 非目标（Out of Scope，v1 不做）

- 云同步/多设备账户体系（仅引导用户用 iCloud / OneDrive / 网盘同步整个目录）
- 多人协作、评论
- 移动端 / Web 版
- 题目本身的内容浏览（不内嵌 LeetCode 题库，只做「题解档案」）
- AI 生成题解/自动解题
- 富媒体附件（图片内嵌本地副本可支持，但不做剪贴板图床）

## 4. 功能需求

> 需求以 `FR-x.y` 编号，正文沿用技术方案的命名（`FileMeta` / `CardRecord` / `SchedulingInfo` 等，见 `docs/technical-design.md` §3）。

### 4.1 题解笔记模块（书写与编辑）

#### FR-1.1 结构化元数据（frontmatter）

每条题解包含：**来源 source**、**题号 id**、**标题 title**、**难度 difficulty（Easy/Medium/Hard）**、**标签 tags（多值）**。以上字段存于 `.md` 文件头部 YAML frontmatter。另支持：`status`（手动状态标记，见 FR-3.4）、`aliases`（双链别名，见 FR-4.2）、复习变量快照（见 FR-2.1）。

- 文件路径约定：`{notesRoot}/{source}/{id}.md`（如 `我的笔记/leetcode/two-sum.md`），文件名稳定不变（编辑 title 不改文件名）。
- **验收**：保存后文件头部 frontmatter 结构合法，可被普通 Markdown 工具解析；新建题解若缺失必填元数据（source/id/title/difficulty/tags），编辑区显示提示条、`Ctrl+S` 前给出警告，但不阻塞先存正文草稿；快速记录落盘后进入补充页完善难度与标签。

#### FR-1.2 多解法支持

一道题允许记录**多种解法**，每种解法独立成块并附带**独立的复杂度分析**。正文约定结构（详见附录 A.1）：

````markdown
## 解法一：暴力
思路 …
```ts
代码…
```
**时间复杂度**：O(n²)　**空间复杂度**：O(1)
````

- **验收**：解析器能区分同一题下的多个解法块并分别展示；阅读模式按「解法一/二/…」分段渲染；复习整题卡时答案区按解法列表呈现。

#### FR-1.3 WYSIWYG 编辑体验

所见即所得编辑（参考 Typora）：所见即正文、正文即 `.md`，无源码/预览割裂。支持：**代码块语法高亮**（适配主流语言）、**LaTeX 数学公式**（用于复杂度推导）、**任务列表**、**双链**、表格、图片。

- **验收**：编辑视图与导出的 `.md` 语义一致（round-trip）；代码块粘贴含语言标注；`$...$`/`$$...$$` 公式实时渲染。
- 技术选型假定为 Tiptap，扩展与 round-trip 细节见技术方案 §7。

#### FR-1.4 编辑器快捷键

编辑态常用快捷键见 §7 表格（加粗、斜体、行内代码、代码块、公式、链接、标题升降、列表缩进等）。**验收**：同一快捷键在 编辑/阅读/复习 三种上下文行为正确、互不污染（见技术方案 §9 冲突策略）。

#### FR-1.5 快速记录浮窗（Ctrl+Shift+N）

任意界面按 `Ctrl+Shift+N` 弹出**快速记录浮窗**：主输入为 Markdown 正文，随输随保存；**从剪贴板粘贴 URL 时自动解析来源与标题**填充元数据（来源规则见技术方案 §5.5）。浮窗提交后落盘为一条题解，进入常规编辑页补充难度/标签/解法。

- **验收**：粘贴 `https://leetcode.com/problems/two-sum/…` 后，浮窗自动填 source=`leetcode`、id=`two-sum`、title=`Two Sum`；提交后在 `{notesRoot}/leetcode/two-sum.md` 生成文件。

#### FR-1.6 自动保存与外部变更

编辑内容自动保存（防抖）；目录被外部工具/网盘改动时，聚焦回到应用能识别并重新加载，避免旧状态覆盖新文件（策略见技术方案 §5.4）。

#### FR-1.7 图片依赖管理（类 Typora）

- 在编辑器中粘贴/拖入图片时，应用把图片副本写入**当前笔记所在目录**下的 `.images/`（如 `Documents/leetcode/.images/`），并在正文以**相对路径**引用（`![](./.images/xxx.png)`），不依赖外部图床。
- 图片文件名自动去重（时间戳/哈希前缀）；同目录多篇笔记共享该 `.images/`；删除笔记中的引用时可清理孤儿图片。
- **验收**：在 `leetcode/two-sum.md` 粘贴图片后，图片落于 `leetcode/.images/` 且正文为相对引用；把整目录（含 `.images/`）拷贝到新机器后图片仍正常显示。

### 4.2 间隔重复复习模块（对抗遗忘）

#### FR-2.1 调度算法与数据（SM-2）

每张调度卡追踪三个核心变量（初始值与技术方案 §5.2 一致）：

| 变量 | 含义 | 初值 |
|---|---|---|
| `repetitions` | 连续答对次数 | 0 |
| `easeFactor`（EF） | 难度因子 | 2.5，**下限 1.3** |
| `interval` | 距下次复习天数 | 0 |

另辅助记录 `due`（下次到期日，本地自然日）、`lapses`（累计答错）、`lastReviewed`（最近评分日，见技术方案 §3.3 `SchedulingInfo`）。

- **存储位置**：复习变量作为**权威数据写入 `.md` frontmatter 的 `scheduling:` 块**（保证文件自包含、可重导入）；SQLite `cards` 表只是为到期查询/检索建立的**可重建索引**。理由与取舍见技术方案 §3.4。
- **验收**：新题解首次复习成功后 frontmatter 出现 `repetitions/easeFactor/interval/due` 且数值符合调度规则；删除 SQLite 后仅凭 `.md` 目录可完整重建全部卡片与到期队列。

#### FR-2.2 评分映射与调度规则

复习时用户按 **1=Again 2=Hard 3=Good 4=Easy** 自评。调度规则为「经典 SM-2 公式 + 四档评分映射」，逐条锁定如下（数值演算见技术方案 §5.2）：

| 档位 | 质量分 q | 语义 | 规则 |
|---|---|---|---|
| 1 Again | q=1 | 忘记/答错 | 重置：`repetitions→0`、`interval→1`；**保留当前已调整的 EF**（失败步不修改 EF） |
| 2 Hard | q=3 | 勉强通过 | `repetitions+1`；按 SM-2 公式小幅下调 EF（`EF−0.14`，下限 1.3） |
| 3 Good | q=4 | 正常 | `repetitions+1`；EF 不变 |
| 4 Easy | q=5 | 很熟 | `repetitions+1`；EF 上调（`EF+0.10`） |

成功步间隔取值：`repetitions==1 → interval=1`；`repetitions==2 → interval=6`；之后 `interval = round(interval × EF)`。EF 更新仅作用于成功档（q≥3），失败档只重置短间隔、不改 EF —— 对应产品诉求「答错时重置短间隔队列，但保留调整后的 easeFactor」。

- **验收**：对同一 `SchedulingInfo` 分别打分 1/2/3/4 后，输出与 §5.2 公式逐项一致；EF 永不低于 1.3；因 `Again` 回到第 1 天的新间隔从 1 天重新起步。

#### FR-2.3 复习对象：整题卡 + 拆解卡

- **整题卡**：每道题默认一张卡。复习面 = 「回顾 {标题} 的完整解法」，答案面 = 动态聚合该题全部解法块（含复杂度）。整题卡调度变量即 FR-2.1 所述 frontmatter 顶层调度。
- **拆解卡**：用户可在正文内嵌独立问答块 `问题::答案`（约定见附录 A.2），每块派生一张独立调度的卡（如把「二分的循环不变量是什么」单独抽卡）。拆解卡调度存于 frontmatter `scheduling.cards` 映射（键由问题文本稳定派生），**拆解卡存在与否不影响整题卡**。
- **验收**：新建题解自动获得整题卡并进入调度；在正文添加一条 `问题::答案` 后，卡片列表出现第二张独立卡且有自己的 due；删除该块后对应卡被回收，整题卡不受影响。

#### FR-2.4 复习会话流（键盘驱动）

```
进入今日队列 → 展示题目/问题面 →（回忆）→ 空格 → 显示答案 → 1/2/3/4 键自评 → 自动下一张
```

- 会话内**独占键盘**：空格/数字键不进入编辑器、不滚动误触；误触评分可用 `U` 撤销（见下）。
- 会话结束统一提交评分，批量、原子地写回 `.md` frontmatter 与 SQLite（见技术方案 §5.3 / §5.4）。
- 支持单卡「撤销上一步评分」快捷键 `U`。
- 底部状态栏在会话中显示队列进度 `3/10`（见 §6 布局）。
- **验收**：10 张到期卡全程可用 `空格 / 1-4 / Esc` 完成，0 次鼠标点击；中途 `Esc` 退出已评分卡不丢失；会话期间按字母键不会在正文输入字符。

#### FR-2.5 复习策略控制

- 每日新卡数量上限（可设，默认 20；到达上限后新卡延后到次日）。
- 复习范围过滤：**按标签**（如仅 DP 标签）、**按难度**、**按上次复习时间**组合。
- **验收**：设新卡上限后今日队列新卡数不超限；过滤 DP 标签后队列仅含命中卡；到期卡优先于新卡出队。

### 4.3 组织与管理模块（检索与洞察）

#### FR-3.1 全文与组合检索

- 全文**模糊搜索**（标题 + 正文 + 标签；针对中文的分词策略见技术方案 §5.6）。
- **多条件组合筛选（AND/OR）**，示例查询：
  - `难度=Hard AND 标签=动态规划`
  - `难度=Easy OR 标签=数组`，再与 `上次复习>7天` 组合。
- **验收**：上述示例 5 秒内返回正确集合；中文片段（如搜「环形链表」）能命中含该词正文。

#### FR-3.2 知识地图

自动生成**标签聚合页**（每标签→题目列表与平均到期量）与**难度分布**视图。

#### FR-3.3 仪表盘（进度洞察）

- 指标：总题数、各难度占比、标签覆盖率。
- **复习表现趋势**：每日正确率曲线（正确率 = 当日 评分≥3 的复习 ÷ 当日复习总数）。
- **薄弱环节自动高亮**：对每个标签统计近 N（默认 30）天内复习样本，当「样本 ≥5 且 正确率 < 60%」时判定为薄弱，在标签云/看板高亮并聚合「薄弱题集」入口。
- **验收**：正确率曲线按天聚合准确；将某标签造出 5 次中 4 次 Again 的历史后，该标签出现在薄弱高亮中。

#### FR-3.4 自定义状态标记

手动为题目打状态标签：`待二刷` / `已掌握` / `需深入`（存 `status` 字段；无标记时缺省为 `active`）。状态可参与 FR-3.1 组合筛选。

### 4.4 阅读与沉淀模块（回顾与输出）

#### FR-4.1 双模式切换

`编辑模式` ⇄ `沉浸阅读模式`（一键切换，见 §7）：阅读模式隐藏全部编辑控件、自动生成文章大纲（TOC，取自 heading）供点击跳转，代码/公式静净渲染。

#### FR-4.2 双向知识关联

- 支持 `[[另一道题名]]` 语法建立题解间引用，形成反向链接列表（`backlinks`）。
- 自动推荐**同标签关联题目**（展示在右栏，见 §6）。
- **验收**：在 A 的正文写 `[[two-sum]]` 后，B（two-sum）的右栏反向链接出现 A；同标签推荐 Top 5 合理。

#### FR-4.3 导出

单篇或整集导出为 **Markdown / PDF / HTML**。Markdown 导出分两种版本：
- **分享版**（默认）：剥离 `scheduling` 块，只留题目元数据，便于发布/分享；
- **备份版**：完整保留 frontmatter（含 `scheduling`），可整目录回导无损恢复。

- **验收**：备份版导出后可整目录重新导入且调度与到期不丢；分享版 frontmatter 不含 `scheduling`；PDF/HTML 中文、代码块与公式正常。

````markdown
# Two Sum

> 给定整数数组与目标值，返回两数下标，使和等于目标值。

## 解法一：哈希表

一遍遍历，边存边查补数。

```python
def twoSum(nums, target):
    seen = {}
    for i, n in enumerate(nums):
        if target - n in seen:
            return [seen[target - n], i]
        seen[n] = i
```

**时间复杂度**：O(n)　**空间复杂度**：O(n)

## 解法二：暴力

两重循环枚举。**时间复杂度**：O(n²)　**空间复杂度**：O(1)

### 卡片

- 能否用排序+双指针解这题？为什么不行？:: 排序双指针要求返回下标，排序会丢失原下标，需额外记录，得不偿失
- 哈希表解法为何能到 O(n)？:: 每步查找与插入均摊 O(1)，整体 O(n) 一次遍历

### 关联

相似思想见 [[three-sum]]；[[两数之和]] 相关标签：array、hash-table。
````
